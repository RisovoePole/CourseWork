# ПЛАН ЭКСПЕРИМЕНТА

## Тема

Сравнительный анализ точных и метаэвристических алгоритмов в задаче комбинаторной оптимизации расписания.

### ЭТАП 1. Подготовка тестовых данных (Бенчмарков)

Поскольку алгоритмы имеют принципиально разную вычислительную сложность, мы разделим входные данные на 3 класса размерности. Каждый класс генерируется в 10 случайных вариациях (для исключения статистических аномалий).

Размерность задачи = Курсы × Дни × Слоты × Кабинеты

| Класс теста | Размерность (N занятий) | Цель |
|---|---:|---|
| S (Small) | $N = 10..15$ | Валидация всех алгоритмов. Поиск глобального оптимума Полным перебором. |
| M (Medium) | $N = 100..150$ | Основное поле боя. Точные методы могут начать буксовать, метаэвристики должны раскрыться. |
| L (Large) | $N = 500+$ | Стресс-тест на масштабируемость и экономию памяти. |

### ЭТАП 2. Метрики для сравнения (KPI)

Каждый запуск алгоритма на тесте оценивается по трем критериям:

- Качество решения (Fitness Score / Cost): Количество нарушенных жестких и мягких ограничений (цель — минимизация штрафов до 0).
- Время работы (Execution Time): Время до выдачи финального ответа (в миллисекундах).
- Стабильность (для стохастических методов): Среднеквадратичное отклонение качества решения по итогам 20 перезапусков на одном и том же датасете.

### ЭТАП 3. Конфигурация участников (Особенности реализации)

Перед запуском фиксируем базовые настройки для каждого алгоритма:

- Полный перебор (Brute Force):

  - Реализация: Итеративный бэктрэкинг со стеком.
  - Особенность: Ограничение по времени (Timeout) = 5 минут. Если не успел — пишем «N/A (Time Limit Exceeded)».

- Программирование в ограничениях (Constraint Programming / CP):

  - Реализация: Использование готового промышленного солвера (например, Google OR-Tools CP-SAT).
  - Особенность: Служит эталоном эффективного точного поиска.

- Имитация отжига (Simulated Annealing):

  - Параметры: \(T_{start} = 1000\), \(\alpha = 0.98\), одноточечная мутация (замена кабинета или слота у одного случайного занятия).

- Поиск с запретами (Tabu Search):

  - Реализация: Локальный поиск, который шагает в лучшее соседнее состояние (даже если оно хуже текущего), но хранит историю последних \(K\) шагов в Tabu-листе, запрещая возвращаться в них, чтобы не зациклиться.
  - Параметры: Размер Tabu-листа = 15 элементов.

- Генетический алгоритм (Genetic Algorithm):

  - Параметры: Популяция = 100 особей, турнирный отбор, элитарность (сохранение лучших 5%), вероятность мутации = 10%.

### ЭТАП 4. Порядок проведения запусков

Эксперимент разбивается на три последовательных фазы:

Фаза А. Калибровка на малых данных (Тесты S)

- Цель: Найти математический глобальный оптимум с помощью Полного перебора и CP.
- Результат: Проверить, способны ли ГА, Отжиг и Табу приближаться к 100% качеству на простых задачах.

Фаза Б. Основное сравнение (Тесты M)

- Цель: Оценить падение эффективности точных методов и скорость сходимости эвристик.
- Результат: Определение «золотой середины» (какой алгоритм дает лучшее качество за приемлемое время, например, до 30 секунд).

Фаза В. Стресс-тест (Тесты L)

- Цель: Проверка на масштабируемость.
- Результат: Скорее всего, Полный перебор упадет сразу, CP-солвер выдаст первое допустимое решение, но не успеет его оптимизировать. Метаэвристики (ГА, Отжиг, Табу) покажут, кто из них лучше держит удар при росте объема данных.

### ЭТАП 5. Ожидаемая структура отчета и графики

По результатам сводных JSON/CSV таблиц строятся три финальных графика:

- Диаграмма рассеяния «Время vs Качество»: По оси X — время решения, по оси Y — качество (штрафы). Идеальный алгоритм должен стремиться к левому нижнему углу (быстро и без штрафов).
- График масштабируемости: По оси X — размер задачи (S, M, L), по оси Y — время (логарифмическая шкала). Покажет экспоненциальный взрыв перебора и линейный/полиномиальный рост эвристик.
- Матрица попарного сравнения метаэвристик: Сравнение Имитации отжига, Поиска с запретами и ГА между собой по стабильности результатов при случайных запусках.
