# Genetic Algorithm — `scheduling_ga.py` (DEAP)

## Как работает именно эта реализация

1. Особь = `list[Gene]` длиной `len(sessions)`, **позиционное** кодирование: ген `i` — это всегда решение для `sessions[i]` (никакой перестановки/перекодировки порядка, в отличие от индирект-кодирования в Java-GA). `Gene = (weekday_id, timeslot_id, audience_id, professor_id)`.
2. `random_gene` (используется и при инициализации, и при мутации) фильтрует только по `professor_discipline` и `optimal_room_type` — вместимость и дневной лимит не учитываются ни при генерации, ни при мутации, их обязана выправить давление фитнеса.
3. Фитнес — **скаляризация** `(hard, soft)` из `evaluate()` в одно число: `hard * 1000 + soft`, потому что `FitnessMin` у DEAP однокритериальный (`weights=(-1.0,)`). Лексикографики тут нет, она симулируется весом.
4. Кроссовер — `tools.cxTwoPoint`: меняет местами **целые гены** между двумя точками разреза. Поля внутри одного гена (weekday/timeslot/audience/professor) между родителями никогда не смешиваются.
5. Мутация — `mutate_individual`: с вероятностью `indpb` (0.1) ген **полностью перегенерируется** через `random_gene` (не точечная правка одного поля, а бросок кубика по всем четырём сразу).
6. Цикл — стандартный `algorithms.eaSimple`: select → varAnd (mate+mutate) → evaluate → `halloffame.update(offspring)` → население заменяется потомками целиком. **Элитизм не встроен**: лучшая особь хранится только в `HallOfFame` для финального ответа, в живую популяцию она не возвращается, если потомки её "потеряли".

## Что крутить и как понять, что крутить

| Параметр | Эффект | Когда трогать |
|---|---|---|
| `population_size` (100) / `generations` (200) | классический объём поиска | `hard` не доходит до 0 или soft высокий и не падает на `result.logbook` → увеличить оба |
| `cx_prob` (0.6) | доля потомков от рекомбинации | мало улучшений за поколение → можно увеличить, чтобы чаще комбинировать удачные куски разных особей |
| `mut_prob` (0.3) | доля потомков, попадающих под мутацию | застой/преждевременная сходимость (см. ниже) → увеличить |
| `gene_mut_indpb` (0.1) | доля генов внутри особи, перегенерируемых при мутации | слишком резкие скачки качества между поколениями → уменьшить; слишком медленный прогресс → увеличить |
| `tournsize` в `selTournament` (зашит как 3, не параметр функции) | давление селекции | подозрение на преждевременную сходимость (популяция быстро становится однородной) → уменьшить; слишком медленная сходимость → увеличить — но руками в коде |
| `HARD_PENALTY_WEIGHT` (модульная константа, 1000) | насколько hard важнее soft | если soft-метрики у тебя в данных регулярно превышают пару сотен — поднять вес, иначе скаляризация может потерять приоритет hard |

Диагностика: смотреть `result.logbook.select("min")` / `.select("avg")` по поколениям (сейчас `verbose=False`, значит в консоль это не печатается — доставать вручную). Если `min` фитнеса застыл задолго до `generations` — либо популяция слишком однородна (поднять `mut_prob`/`tournsize` ниже), либо `population_size` мал для размера задачи.

## Особенности реализации

- `creator.create` обёрнут в `hasattr`-проверку — без этого повторный вызов `genetic_algorithm()` в одном процессе (например, в цикле бенчмарка с разными seed) кидает предупреждение/может вести себя не так, как ожидаешь, при повторной регистрации тех же имён классов.
- Встроенные операторы DEAP (`cxTwoPoint`, `selTournament`) сидят на **глобальном** модуле `random`, а не на отдельном `Random`-инстансе. Поэтому сидирование идёт через `random.seed(seed)` глобально — если в том же процессе до или после GA что-то ещё трогает глобальный `random` (например, TS или SA с собственным `random.Random`, что у них и сделано), воспроизводимость самого GA-прогона это не ломает, но делает его менее изолированным, чем TS/SA.
- DEAP сам инвалидирует и пересчитывает fitness только у изменённых потомков (это плюс самого `eaSimple`, не моя добавка — но именно поэтому evaluate() не вызывается зря на неизменных особях).

## Чем плох / недоработки

- Нет элитизма в живой популяции — лучшая когда-либо найденная особь физически может выпасть из population и не использоваться для дальнейшего скрещивания; в финальный ответ она попадёт (через `HallOfFame`), но в поиске не участвует повторно.
- Инициализация и мутация игнорируют вместимость аудитории и дневной лимит — то же самое ограничение, что и в TS, здесь оно вдвойне дороже, потому что **вся** борьба с этими hard-constraint'ами идёт только через давление фитнеса по всей популяции, а не через локальный ремонт одного решения.
- `HARD_PENALTY_WEIGHT` — захардкоженная модульная константа, не параметр `genetic_algorithm()`.
- Мутация — это всегда "бросить заново", а не точечная правка одного поля (как отдельные ходы reslot/reaudience/reprofessor в TS) — более грубый инструмент, сложнее настроить тонкую доводку под конец прогона.
- Нет адаптивного снижения силы мутации к концу прогона (нет аналога охлаждения, как в SA) — на поздних поколениях так же легко всё сломать одной мутацией, как и на первых.
- Никакой параллелизации оценки популяции — DEAP это поддерживает (`toolbox.register("map", ...)`), но не подключено.

## Точки расширения

- `toolbox.register` — любой из mate/mutate/select можно заменить одной строкой (например, `tools.cxUniform` вместо `cxTwoPoint` для более разрушительного скрещивания).
- `mutate_individual` легко разбить на отдельные подвиды мутации (только слот / только аудитория / только преподаватель) по аналогии с ходами TS — сейчас это один грубый оператор.
- `to_algorithm_run_record` уже совместим со схемой `algorithm_runs` — для бенчмарка ничего докручивать не нужно.

## Что стоит добавить

- Явный элитизм: либо вручную реинжектить лучшую особь из `HallOfFame` обратно в популяцию перед селекцией, либо перейти на `eaMuPlusLambda`, где элитизм встроен в саму схему `(μ+λ)`.
- Адаптивное `gene_mut_indpb` — уменьшать к концу прогона для более тонкой доводки.
- Параллельная оценка фитнеса (`multiprocessing.Pool` через `toolbox.register("map", ...)`) — самое дешёвое ускорение при большой популяции.
- Параметризация `HARD_PENALTY_WEIGHT` и `tournsize` через сигнатуру функции.
